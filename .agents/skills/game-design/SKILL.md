# Game Design

## Goal
Define a game around what the player repeatedly does and feels, not around a feature inventory.

## Process
1. State the player fantasy in one sentence.
2. Define the core loop in 3-6 steps.
3. List the essential player verbs.
4. Identify the primary source of interesting decisions or tension.
5. Define feedback: what the player sees/hears/understands after an action.
6. Remove systems that do not strengthen the core loop.
7. Define the first playable slice that can test the central claim.
8. Update `docs/GAME_DESIGN.md` when the concept becomes durable.

## Evaluation questions
- What decision does the player make repeatedly?
- What can the player get better at understanding or doing?
- What prevents the optimal action from being trivial?
- What would still be fun if progression rewards were removed?

## Handoff
Use `prototyping` once one central gameplay hypothesis is specific enough to test.
